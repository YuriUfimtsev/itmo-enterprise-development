#### Регистрация посетителя (Member)
1. Администратор входит в Систему и вводит имя, фамилию, дату рождения, email-адрес посетителя (Member).
2. Система проверяет наличие пользователя с данным email-адресом.
3. Если пользователь не найден, Система создает нового пользователя в качестве посетителя (Member) без абонемента (Subscription).

*Альтернативы*
    
-  3a. Если пользователь с таким email-адресом найден в качестве посетителя (Member), Система возвращает сообщение об ошибке: “Ошибка: посетитель {Имя} {Фамилия} {Год рождения} года рождения уже зарегистрирован по данному email-адресу”.


- 3б. Если пользователь с таким email-адресом найден в качестве администратора, Система возвращает сообщение об ошибке: “Ошибка: данный email-адрес используется администратором системы”.


#### Регистрация тарифного плана (RatePlan)
1. Администратор входит в Систему, вводит политику (Policy) и параметры тарифного плана (RatePlan):
    - продолжительность (daysDuration) и цена (price) для плана c политикой неограниченного доступа (“Unlimited”);
    - продолжительность (daysDuration), цена (price), ежедневное время открытия доступа на вход (timeFrom), ежедневное время закрытия доступа на вход (timeTo) для плана c политикой временного окна (“TimeWindowPolicy”);
    - продолжительность (daysDuration), цена (price), допустимое количество посещений в неделю (weeklyLimit) для плана c политикой ограничений в неделю (“WeeklyLimitPolicy”).
2. Система проверяет, что указана одна из трёх политик и для неё заполнены необходимые параметры.
3. Если проверка успешна, Система проверяет наличие активного (isActual == true) тарифного плана (RatePlan), совпадающего по всем показателям кроме цены (price). 
4. Если активный тарифный план (RatePlan) не найден, Система создаёт новый тарифный план (RatePlan) с указанными на шаге 1 политикой (Policy) и параметрами, далее Система возвращает идентификатор нового тарифного плана.

*Альтернативы*

- 3а. Если указана несуществующая политика (Policy) или для указанной политики заполнены лишние параметры или заполнено недостаточно параметров, Система возвращает соответствующее сообщение об ошибке:
    - “Ошибка: политика {введенное имя политики} не существует. Доступные политики: {перечисление ранее добавленных политик}”;
    - “Ошибка: для политики {введенное имя политики} заполнены лишние параметры {перечисление лишних заполненных параметров}”;
    - “Ошибка: для политики {введенное имя политики} не заполнены обязательные параметры {перечисление обязательных незаполненных параметров}”.

4а. Если активный тарифный план (RatePlan), совпадающий по политике (Policy) и всем параметрам кроме цены (price) найден, Система возвращает сообщение об ошибке: “Ошибка: тарифный план с указанными параметрами уже существует (id = {id}). Пожалуйста, воспользуйтесь функцией обновления цены существующего тарифного плана”.


#### Назначение тарифного плана (RatePlan) на посетителя (Member)
1. Администратор входит в систему и вводит идентификатор тарифного плана (RatePlan), почту посетителя (Member).
2. Система проверяет, что активный (isValid == true) тарифный план (RatePlan) с указанным идентификатором и посетитель с указанной почтой существуют.
3. Если проверки успешны, Система устанавливает в объекте Subscription пользователя идентификатор тарифного плана, также устанавливает from в текущий день, to – в текущий день + кол-во дней тарифного плана (daysDuration у RatePlan). 

*Альтернативы*

3а. Если активный тарифный план (RatePlan) с введенным идентификатором или посетитель (Member) с указанной почтой не найдены, Система возвращает соответствующее сообщение об ошибке:
- “Ошибка: тарифный план с идентификатором {введенный идентификатор} не найден”;
- “Ошибка: посетитель с почтой {введенная почта} не найден”.


#### Регистрация посещения (Attendance) с проверкой доступа
1. В Систему с учетными данными (актуальным JWT-токеном) администратора поступает запрос на посещение (Attendance), содержащий идентификатор посетителя (Member).
2. Система фиксирует текущую дату и время, проверяет, что посетитель (Member) с переданным идентификатором существует
3. Система проверяет, что абонемент (Subscription) ещё актуален: сравнивает значение to с текущей датой.
4. Если проверка успешна, Система на основе политики (Policy) тарифного плана (RatePlan) пользователя, времени и даты запроса, информации о предыдущих посещениях (Attendance) принимает решение о пропуске посетителя:
при политике Unlimited – true;
при политике TimeWindowPolicy – на основе времени и даты запроса, timeFrom и timeTo в тарифном плане (RatePlan);
при политике WeeklyLimitPolicy – на основе количества посещений (Attendance) за последнюю неделю и значении weeklyLimit в тарифном плане (RatePlan).
5. Система фиксирует причину результата в строке:
 если решено пропустить, строка пустая;
если решено отказать в доступе
для политики TimeWindowPolicy – “Текущее время не попадает в интервал доступа посетителя”;
для политики WeeklyLimitedPolicy – “Количество доступных посещений в течение недели исчерпано”.
6. Система сохраняет информацию о посещении (Attendance): идентификатор пользователя, дата и время запроса, решение о пропуске (true или false), строку причины.
7. Система возвращает решение о пропуске и строку причины.

*Альтернативы*

- 2а. Если посетитель (Member) с переданным идентификатором не найден, Система возвращает сообщение об ошибке: “Ошибка: посетитель с идентификатором {переданный идентификатор} не найден”.

- 3а. Если проверка завершилась неуспешно, Система сохраняет информацию о посещении (Attendance): идентификатор пользователя, дата и время запроса, false в поле результата посещения и строку “Не найден актуальный абонемент посетителя” в поле причины.
Система возвращает поле результата посещения и строку причины.








##### Поиск пользователя по email-адресу
1. Администратор входит в Систему, вводит email-адрес пользователя. 
2. Система проверяет наличие пользователя с данным email-адресом.
3. Если пользователь найден, система возвращает имя, фамилию, дату рождения, почту и информацию о том, является ли пользователь админом.

*Альтернативы*

- 3а. Если пользователь с указанной почтой не найден, Система возвращает сообщение об ошибке: “Ошибка: пользователь с почтой {переданная почта} не найден”.


##### Обновление цены тарифного плана
1. Администратор входит в Систему, вводит идентификатор и новую цену тарифного плана (RatePlan).
2. Система проверяет, что активный (isActual == true) тарифный план (RatePlan) с введенным идентификатором существует.
3. Если активный тарифный план (RatePlan) с введенным идентификатором существует, Система обновляет цену тарифного плана.

*Альтернативы*

- 3а. Если активный тарифный план (RatePlan) с введенным идентификатором не найден,Система возвращает сообщение об ошибке: “Ошибка: тарифный план с идентификатором {введенный идентификатор} не найден”. 


##### Поиск тарифных планов (RatePlan)
1. Администратор входит в Систему, заполняет от 0 до общего количества полей тарифного плана (RatePlan): в поля входит политика (Policy) и параметры. 
2. Система выполняет поиск активных (isActual == true) тарифных планов, удовлетворяющих заданным условиям. Если заполнено 0 полей, система ищет все активные тарифные планы.
3. Система возвращает найденные планы в количестве от 0 до общего числа активных планов.

#### Удаление тарифного плана (RatePlan)
1. Администратор входит в Систему, вводит идентификатор тарифного плана (RatePlan).
2. Система проверяет, что активный (isActual == true) тарифный план (RatePlan) с введенным идентификатором существует.
3. Если активный тарифный план (RatePlan) с введенным идентификатором существует, Система делает план неактивным, выставляя isActual у RatePlan в false.

*Альтернативы*

- 3а. Если активный тарифный план (RatePlan) с введенным идентификатором не найден, Система возвращает сообщение об ошибке: “Ошибка: тарифный план с идентификатором {введенный идентификатор} не найден”. 


##### Регистрация нового администратора
0.  Новый администратор вводит в Систему имя, фамилию, дату рождения, email, придумывает пароль.
1. Система сохраняет профиль со статусом «Ожидает подтверждения»
2. Действующий администратор подтверждает регистрацию нового администратора в Системе, используя почту нового администратора.

##### Аутентификация администратора
1. Администратор вводит почту и пароль в Систему.
2. Система проверяет корректность данных.
3. Если данные верны, система генерирует и возвращает JWT-токен с ограниченным сроком действия.
4. Администратор получает доступ к системе

*Альтернативы*

- При истечении срока действия JWT-токена администратор повторно проходит аутентификацию: вводит в систему логин и пароль / использует refresh токен.
